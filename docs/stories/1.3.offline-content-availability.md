# Story 1.3: Offline Content Availability and Visual Indicators

## Status

Done

## Story

**As a** student,
**I want** to clearly see which modules I have successfully downloaded and be able to access them completely offline,
**so that** I can confidently study without worrying about internet connectivity.

## Acceptance Criteria

1. Downloaded modules display a clear visual indicator (e.g., checkmark icon, "Offline Available" badge)
2. When offline (no internet connection), the app displays all downloaded modules normally
3. When offline, attempting to access a non-downloaded module shows a clear message: "This module is not available offline. Please download it when you have internet access."
4. All module assets (audio files, PDFs, images, quiz data) are fully accessible offline after download
5. The app works correctly when switching between online and offline modes
6. Downloaded content persists across app sessions (closing and reopening the app)

### Architecture: Offline Strategy

**Service Worker Cache-First Strategy:**

The service worker implements a cache-first strategy where:

1. Service Worker intercepts all asset requests
2. Checks Cache API for cached version first
3. Returns cached asset immediately if available (no network request)
4. Only fetches from network if asset not in cache

**Asset Serving Pattern:**

All module assets (audio, PDFs, images) located in `public/` directory:

- Audio files: `public/audio/*.mp3`
- PDF workbooks: `public/pdfs/*.pdf`
- Module images: `public/images/*.png`

Service worker caches these using full URLs (e.g., `/audio/orientation-intro.mp3`).

**Offline Detection:**

Use `navigator.onLine` API to detect current network status:

- `navigator.onLine` returns `true` when online, `false` when offline
- Listen for `online` and `offline` events on `window` object for real-time updates

[Source: docs/front-end-architecture.md - Section 4: Data & Offline Strategy]

### Architecture: Persistent Storage

**Storage Persistence API:**

To prevent browsers from evicting cached content, use the Storage API:

```typescript
// Request persistent storage
if (navigator.storage && navigator.storage.persist) {
  const isPersisted = await navigator.storage.persist();
  console.log(`Persistent storage granted: ${isPersisted}`);
}
```

**When to Request Persistence:**

- Request on app initialization (root layout or service worker registration)
- Browser may show user prompt to grant permission
- Not all browsers support this API (fallback gracefully)

**Why This Matters:**

- Without persistence, browsers can evict cached content under storage pressure
- With persistence, downloaded modules are protected from automatic eviction
- Critical for students who rely on offline access for extended periods

[Source: Web Storage API documentation, PWA best practices]

### Risks & Mitigations

**Risk:** Browser storage eviction under storage pressure

**Mitigation (for this story):**

- Implement persistent storage request via `navigator.storage.persist()`
- Request on app initialization
- Log persistence status for debugging

**Risk:** False offline detection (browser reports online but network is slow/unstable)

**Mitigation (for this story):**

- Rely on `navigator.onLine` as primary indicator
- Service worker cache-first strategy ensures offline works even with unreliable network
- Future stories could add network quality detection

**Risk:** Incomplete cache (not all assets downloaded successfully)

**Mitigation (for this story):**

- Assume Story 1.2 download process completed successfully
- Future stories can add cache validation to verify all assets present
- For now, rely on "downloaded" status in IndexedDB as source of truth
